# Definition of Ready (DoR)

## 1. Cel

Definition of Ready określa minimalne warunki, które zadanie powinno spełniać przed rozpoczęciem jego realizacji.

Zadanie spełnia Definition of Ready, jeśli:

- [ ] Ma jasny i zrozumiały tytuł.
- [ ] Zawiera opis zakresu pracy.
- [ ] Określa oczekiwany rezultat.
- [ ] Posiada kryteria akceptacji, jeśli są potrzebne.
- [ ] Ma przypisany typ:  `Feature`, `Bug` lub `Task`.
- [ ] Ma ustawiony priorytet: `High`, `Medium` lub `Low`.
- [ ] Ma przypisaną osobę odpowiedzialną, jeśli została już wybrana.
- [ ] Nie zawiera niejasności uniemożliwiających rozpoczęcie pracy.

## 2. Estymacja

Zadania estymujemy przy użyciu Planning Poker.

Stosowana skala:

| Wartość | Znaczenie |
|---|---|
| 1 | Około 1-3 dni pracy |
| 2 | Około 1 tydzień pracy |
| 3 | Zakres obejmujący praktycznie cały sprint ( 2 tygodnie ) |

Estymacja jest orientacyjną oceną zakresu pracy zespołu, a nie gwarancją czasu realizacji.

Jeżeli zadanie jest zbyt duże lub niejasne, należy rozważyć jego podział albo dalsze doprecyzowanie.

## 3. Status Ready

Po spełnieniu powyższych warunków zadanie może otrzymać status `Ready` w GitHub Projects.

## 4. Uwagi

Definition of Ready jest wewnętrznym uzgodnieniem zespołu RedHero. Nie jest obowiązkowym elementem Scrum Guide.
