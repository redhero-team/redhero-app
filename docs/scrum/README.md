# Dokumentacja Scrum — RedHero

## Cel dokumentacji

Dokumentacja opisuje sposób organizacji pracy zespołu RedHero, zarządzania zadaniami oraz realizacji kolejnych sprintów.

Jej celem jest zapewnienie przejrzystego i powtarzalnego procesu pracy bez wprowadzania niepotrzebnej biurokracji.

## Zespół

Zespół składa się z 4 osób:

| Rola | Liczba osób |
|---|---:|
| Product Owner | 1 |
| Scrum Master | 1 (ta sama osoba co PO) |
| Developers | 3 |

Product Owner pełni również funkcję Scrum Mastera.

## Organizacja pracy

| Element | Narzędzie / zasada |
|---|---|
| Zarządzanie zadaniami | GitHub Issues |
| Tablica projektu | GitHub Projects |
| Repozytorium i kontrola wersji | GitHub |
| Komunikacja i spotkania | Microsoft Teams |
| Estymacja | Planning Poker |
| Retrospektywa | Lucidspark |
| Długość sprintu | 3 tygodnie |

## Statusy zadań

Zadania w GitHub Projects przechodzą przez następujące statusy:

`Backlog → Ready → In Progress → In Review → Done`

## Typy zadań

## Typy zadań

- `Feature` — nowa funkcjonalność lub rozszerzenie istniejącej.
- `Bug` — błąd wymagający naprawienia.
- `Task` — pozostałe prace techniczne, organizacyjne i utrzymaniowe.

## Priorytety

- `High` — najwyższy priorytet.
- `Medium` — średni priorytet.
- `Low` — niski priorytet.

Kolejność rozpatrywania zadań: High, następnie Medium, a na końcu Low.
